## Staging handoff

- **AI Save:** The recorded staging `resolve-place` v18 deployment requires `STAGING_PROVIDER_USERS` and `STAGING_RESOLVE_PLACE_ENABLED=true`. The reviewed `ai-proxy` candidate has the same allowlist and requires `STAGING_ANDROID_PROVIDERS_ENABLED=true`; confirm the live version before changing it. Flipping flags alone will still deny ordinary users. Approve a staging-only update to both function wrappers so a valid Supabase user can use extraction and verification without synthetic admission. Keep the exact Places matcher, allowed origins, function switches, request limits, per-user limits and backend-only `OPENROUTER_API_KEY` and `GOOGLE_MAPS_API_KEY`.
- **Spending controls:** Inspect the actual `staging_provider_control` SQL and campaign row before opening admission. Use a funded, capped soft-launch budget and retain atomic call reservation, deduplication, fail-closed handling and reconciliation. Remove any synthetic-only campaign request-count ceiling while keeping an aggregate spend cap. The local wrapper artifacts show the RPC contract but do not establish the deployed SQL or remaining budget. Keep `https://localhost` allowed for Android. Global bypass of staging controls is unnecessary.
- **Quick Share:** The workflow checks the public venue route and anonymous recommendation read. For new Android shares, confirm the staging `publish_venue_recommendation` and `publish_standalone_venue_recommendation` RPCs and open the generated links signed out. The recommendation snapshot contains name, address, type and source link. Shared collection privacy is a separate, unresolved database issue under ROB-24; do not use shared collections containing private notes for this pilot.
- **Planning:** Use saved venues or existing picks. If route estimates are unavailable, choose the existing distance fallback with a starting location and venues with coordinates. The staging resolver explicitly excludes `travel-times`; routing is not part of the proposed AI Save provider change. Validate an invite as a signed-out recipient. Until ROB-24 is deployed, skip optional RSVP decline reasons in the pilot; the legacy backend setter lacks the authorization added in the pending batch.
